# Methodology, provenance, and compatibility

This document is the durable record of what the analyzer computes, where the
data comes from, what compatibility is claimed, and which deviations are
deliberate. The README covers use; this covers evidence.

## Method

The composite score implements the upstream EQ-Bench slop-score method:

- **slop_words** (weight 0.60): rate per 1k tokens of hits against the
  upstream AI-overused word list (1,648 entries).
- **contrast_patterns** (weight 0.25): rate per 1k characters of stage-1
  "not X, but Y"-family contrast-pattern matches.
- **slop_trigrams** (weight 0.15): rate per 1k tokens of hits against the
  upstream trigram list (430 entries).

Each rate is padded-min-max normalized against calibration ranges and
clamped to [0, 1]; the weighted sum is scaled to 0-100 and emitted
unrounded in JSON. Upstream applies the same weights and normalization.

Beyond the scored components, the analyzer reports non-scored evidence:
bigram-list hits (evidence only, as upstream treats them), repeated
sentence openings, repeated content trigrams, and descriptive signals
(vocabulary level, sentence/paragraph shape, dialogue frequency, moving
average type-token ratio, sentence-length coefficient of variation).
Findings carry counts, byte-offset locations, excerpts, and short reasons.

## Provenance and reproducibility

- Upstream source: <https://github.com/sam-paech/slop-score>, commit
  `289264ab2a0df1358ef81ced3c259610ea709514` (2025-11-22, "fix slop list
  normalisation bug"), MIT license (full text in
  `testdata/upstream/LICENSE.upstream`; attribution in `NOTICE`).
- Canonical embedded data lives in `slop/data/` and is generated by
  `make data` (`tools/datagen`) from the pinned upstream commit. Every
  file's SHA-256, byte size, and entry count is recorded in
  `slop/data/manifest.json`, together with the leaderboard hash it derives
  from.
- Calibration ranges come from the upstream leaderboard results (23 model
  results plus the human baseline): per-result component rates, then a
  min-max range padded by 10% (`range_buffer: 0.1`). The generated
  `slop/data/calibration.json` replaces the 1.4 MB leaderboard blob at
  runtime while remaining fully regenerable.
- A data or pin change is an inspectable behavioral diff: rerun
  `make data`, `make oracle`, and `make eval`, review
  `git diff slop/data testdata/golden`, then accept or reject explicitly.

## Compatibility claim and its verification

The compatibility mode is named **`eqbench-stage1-fallback`**: the upstream
pipeline with the POS-tagged stage-2 contrast patterns disabled, which is
exactly how the upstream website behaves when its wink-pos-tagger CDN load
fails. The name appears in every report (`score.basis`,
`method.compatibility`) so the basis of a number is never ambiguous.

Verification is differential and offline:

- `testdata/upstream/` vendors the pinned upstream JavaScript as a
  development-time oracle. It reads the canonical `slop/data/` files, so
  oracle and Go analyzer always see the same lists and ranges.
- `make oracle` regenerates committed golden expectations
  (`testdata/golden/*.json`) for the cases in `testdata/cases/`.
- Ordinary `go test` compares the Go implementation against those goldens;
  Node is required only when refreshing goldens, never for testing.

Compatibility scope: composite score, component rates, normalization, and
weights match the oracle on the golden set. Diagnostics added by the Go
analyzer are outside the compatibility claim by construction and are
evaluated separately (below).

## Stage-2 status (measured)

Upstream's full pipeline adds a second contrast stage: wink-pos-tagger
tags the text, verbs are replaced by a `VERB` placeholder, and 35
additional regexes run on the tagged stream. It is not implemented in the
Go analyzer, based on measurement rather than assumption:

- **Measured delta: zero.** With wink-pos-tagger 2.2.2 initialized, scores
  and contrast hits are identical on all 15 behavior-corpus and fixture
  documents, and on probes crafted to match individual stage-2 patterns
  (gerund fragments, "It's not because X. It's because Y", "ain't").
- **Mechanism.** wink-pos-tagger splits contractions ("doesn't" ->
  "does/n't", "It's" -> "It/'s") and emits punctuation as separate tokens
  ("waiting ."). The stage-2 regexes require adjacent punctuation
  (`VERB[.!?]`), intact contractions (`it's`, `don't`), or literal lemma
  tokens, none of which survive that token stream, so the patterns cannot
  match and stage-2 appends no candidates.
- Reproduce with `make stage2-delta` (one-time `npm ci` in
  `testdata/upstream/`; see `testdata/upstream/README.md`).

Conclusion: for the pinned upstream revision, `eqbench-stage1-fallback` is
not a degraded mode. It is the behaviorally complete configuration on
every input measured. If a future upstream revision repairs the stage-2
token stream contract, re-run the delta measurement before reconsidering.

## Deliberate deviations

Named deviations from the upstream JavaScript, kept because they produce
clearer or more useful behavior:

- **Unicode-correct tokenization and spans.** The Go tokenizer is
  Unicode-aware (letters beyond ASCII, curly quotes, em dashes); all
  reported locations are byte offsets into the original text, guaranteed
  rune-aligned. Invalid UTF-8 is replaced with U+FFFD and reported as a
  warning instead of failing.
- **Unrounded score.** JSON carries full precision; rounding is a
  presentation concern of the text renderer only.
- **Bigrams as evidence.** The upstream bigram list is loaded and matched
  but excluded from the composite, matching upstream's own treatment; the
  Go analyzer surfaces hits as non-scored findings instead of dropping
  them.
- **Added diagnostics and signals.** Repeated openings, repeated content
  trigrams, and the descriptive signal block have no upstream counterpart.
  They never feed the composite score.
- **Structured report contract.** Versioned schema, corpus aggregates for
  multi-document runs, deterministic ordering, per-group truncation with
  explicit counts, and sample-size warnings are product additions.

## Behavior-corpus evaluation

`make eval` (`tools/eval`) scores the labeled corpus in `testdata/corpus/`
and reports per-label firing rates. Labels are honest provenance notes
(hand-written or known-origin samples), not ground truth; see
`testdata/corpus/README.md`. Current results:

| label           | docs | mean score | notes                                   |
|-----------------|-----:|-----------:|-----------------------------------------|
| model-like      |    2 |      77.09 | dense word/trigram/contrast findings    |
| legacy-fixture  |    5 |      37.01 | legacy regression samples, mixed origin |
| human-like      |    2 |      12.42 | one essay (23.65) + one review (1.20)   |
| revision-before |    1 |      85.32 | model-style scene draft                 |
| revision-after  |    1 |      11.96 | same scene after a hand revision pass   |
| dialogue-heavy  |    1 |       5.91 | repeated_opening fires (documented FP)  |
| technical       |    1 |       5.41 | necessary repetition stays low-scored   |
| rhetorical      |    1 |       1.20 | intentional anaphora: openings fire     |
| short           |    1 |       1.20 | tiny sample; warnings dominate          |

Decisions this evaluation gates:

- **repeated_opening: kept**, with documented false positives on
  dialogue-heavy and deliberately rhetorical prose. The finding explains
  itself and is non-scored; an agent can weigh it in context.
- **repeated_trigram: kept.** Fires on genuine stock-phrase repetition
  (including once on technical docs, a reasonable prompt to check
  boilerplate) and stays silent on human-like controls.
- **sentence_length_cv: kept as a descriptive signal only.** It separates
  model-like (0.44) from human-like (0.58) and dialogue-heavy (0.86)
  samples directionally, but is too context-dependent to accuse; it has a
  note and no findings.

A diagnostic that cannot survive this corpus (explain, locate, and fire
meaningfully more on model-like than on control prose) is cut or demoted.

## Test strategy

- **Golden differential tests** for the compatibility claim (above).
- **Unit tests** for tokenization, normalization, span mapping, interval
  merging, list matching, scoring, comparison, and report shaping.
- **Fuzz tests** (`make test-fuzz`) over tokenizer spans and whole-report
  invariants: no panics, valid rune-aligned spans, deterministic output.
  Fuzzing found and now guards two real bugs (offset drift on invalid
  UTF-8, a rune-splitting span); the crashers are committed as seed corpus
  under `slop/testdata/fuzz/`.
- **CLI tests** for streams, exit codes, stdin and multi-file behavior,
  limits, exclusions, determinism, and schema stability.
- Gates: `make check` (format, modules, lint, tests) for every change;
  `make audit` adds the race detector and `govulncheck`.
